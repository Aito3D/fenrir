# Per-service quantity and discount on Aito tasks

**Date:** 2026-08-20
**Status:** Approved

## Problem

An Aito task carries four optional services — Scan3D, Modélisation3D, Impression3D,
Usinage. Only Impression3D can be quoted per unit: it owns `impression_quantity` and
`impression_discount_pct`, its editor takes a **unit** price beside a quantity, and its
footer band states what one part costs once the discount is off.

The other three take a single lump cost. A machining job for three identical parts has to
be entered as one pre-multiplied number, which means:

- the operator does the arithmetic by hand, and the unit price is nowhere on the screen;
- the Zoho quote says `Usinage × 1` at the lump rate, so the client's PDF cannot show a
  per-piece rate or a discount column;
- a re-imported quote has no quantity to recover.

## Goal

Give Scan3D, Modélisation3D and Usinage the same quantity + discount treatment
Impression3D already has, end to end: editor, board totals, Zoho export, Zoho import,
read-only panel.

## Non-goals

- No calculator behind machining. The three plain services take a hand-typed unit price;
  nothing computes one for them, so they get no cost-split bar and no "apply computed
  price" button.
- No flat-amount discounts. Percent only, matching the shop's Books org and
  `impression_discount_pct`.
- `impression.quantity` does not move out of `ImpressionDraft`. It is an input to
  `computeImpressionCost`, not merely a line multiplier; relocating it would drag the
  pricing path into this change for no gain.

## The invariant, generalised

`impression_cost` is stored **pre-discount**: it is unit × quantity, and every reader
applies `impression_discount_pct` itself. That rule is extended verbatim to the other
three services.

For every service `S` in (`scan`, `modelisation`, `impression`, `usinage`):

| Field | Meaning |
| --- | --- |
| `S_cost` | Pre-discount total for the line = unit price × quantity. `NULL` = service absent from the job. `0` = quoted free, a real step. |
| `S_quantity` | How many units. `NULL` reads as 1. |
| `S_discount_pct` | Percent off, `NULL` = none. `0` is never stored — a literal "0%" would put a pointless discount column on the client's PDF. |

The two must never double-count: the discount is applied by readers (`net_cost`), never
baked into `S_cost`.

## Data model

Six additive columns on `aito_tasks`, mirroring the impression ones:

```
scan_quantity          INTEGER   NULL
modelisation_quantity  INTEGER   NULL
usinage_quantity       INTEGER   NULL
scan_discount_pct          FLOAT NULL
modelisation_discount_pct  FLOAT NULL
usinage_discount_pct       FLOAT NULL
```

Added in `backend/app/core/database.py:run_migrations()` as six `_safe_execute`
`ALTER TABLE ... ADD COLUMN` statements, the same shape as the existing
`impression_discount_pct` migration. Rows predating the migration read `NULL` for both,
which is exactly "quantity 1, no discount" — so no backfill is needed.

## One net-cost helper instead of four special cases

`cost * (1 - pct / 100)` is currently written out at four sites, each guarded by
`service == "impression"`:

- `backend/app/services/aito_board_rules.py:132` (`summarise`)
- `frontend/src/utils/aitoBoardRules.ts:188` (`summariseTasks`)
- `frontend/src/components/aito/services.ts:42` (`taskSteps`)
- `frontend/src/components/aito/services.ts:97` (`stagesWithWork`)

Four services across four sites is where drift starts. This change adds one function to
each half of the mirrored rule engine:

```python
def net_cost(task, service: str) -> float | None:
    """The service's cost as the quote will state it: pre-discount cost less
    its own percent discount. None when the service is absent from the job."""
```

```ts
export function netCost(task: TaskLike, service: ServiceId): number | null
```

All four sites call it. The two implementations stay pinned against each other by the
existing contract fixture (`frontend/src/__tests__/fixtures/aitoBoardRules.cases.json`,
regenerated by `backend/tests/aito_rules_fixture.py`).

`TaskLike` gains optional `scanDiscountPct` / `modelisationDiscountPct` /
`usinageDiscountPct`, so every existing cost/done literal in tests still compiles; the
Python side reads them with `getattr(..., None)` for the same duck-typing reason
`impression_discount_pct` already does.

## Zoho export

`backend/app/services/aito_quote_export.py`:

- `ExportTask` gains the six fields, all defaulted to `None` so existing call sites and
  test helpers stay valid.
- `impression_rate_quantity(task)` generalises to `rate_quantity(task, service)`,
  returning `(round(cost / quantity), quantity)` for any service. Same reason as before:
  a Books line is `rate × quantity` at `price_precision: 0`, so the rate is the rounded
  per-unit figure and `rate * quantity` is the total the quote can actually express.
- A `discount_of(task, service)` accessor joins the existing `cost_of` /
  `description_of` pair.
- In `build_line_items`, the `if service == "impression"` branch disappears: every line
  gets its own rate/quantity/discount. The `"{pct:g}%"` formatting and the
  falsy-means-omit rule are unchanged.

The description rows are untouched — `_rows` still emits print parameters for impression
only, and an `Info:` row for every service.

## Zoho import

`backend/app/services/aito_quote_import.py`:

`ParsedLine` already carries `.quantity` and `.discount_pct` for **every** line, and
`line.amount` is already rate × quantity (`_line_amount`). `_build_task` simply stops
reading them off the impression line only:

```python
for line in ordered:
    task[f"{line.service}_cost"] = line.amount
    task[f"{line.service}_quantity"] = max(1, round(line.quantity))
    task[f"{line.service}_discount_pct"] = line.discount_pct
```

The task dict's initialiser declares `S_cost`, `S_quantity` and `S_discount_pct` as
`None` for all four services (today it declares them for impression only), and the loop
above fills in whichever services the quote actually carried. A service with no line
therefore keeps `None` for all three, as today.

This preserves the module's governing rule: whatever `aito_quote_export` writes,
`aito_quote_import` reads back unchanged.

## Sync

`backend/app/services/aito_quote_sync.py`:

- `_write_back_rounded_impression` becomes `_write_back_rounded_costs`, looping the four
  services instead of hardcoding impression. Rationale is unchanged: a line is
  `rate × quantity` at `price_precision: 0`, so 2401 over 2 units is unrepresentable, and
  adopting the achievable figure immediately keeps project and quote from disagreeing for
  one poller tick.
- `load_export_tasks` passes the six new fields into `ExportTask`.

## Other backend touch points

- `backend/app/schemas/aito.py` — `AitoTaskBase` gains the six fields:
  `S_quantity: int | None = Field(default=None, ge=1)` and
  `S_discount_pct: float | None = Field(default=None, gt=0, le=100)`. `gt=0` because a 0%
  discount is expressed as null, never stored.
- `backend/app/api/routes/aito.py` — `_task_response` passes the six through.
- `backend/app/services/openrouter.py` — `_task_lines` appends `xN` after a service's
  name when its quantity is greater than 1, so a machining-only project's AI summary does
  not lose the count. Impression's existing `(colour, weight, xN)` detail group is
  unchanged.

## Frontend

### Draft shape (`frontend/src/utils/taskDraft.ts`)

`TaskDraft` gains:

```ts
scanQuantity: number;          // floor 1, like impression.quantity
modelisationQuantity: number;
usinageQuantity: number;
scanDiscountPct: number | null;
modelisationDiscountPct: number | null;
usinageDiscountPct: number | null;
```

All four converters are updated: `emptyTaskDraft`, `normaliseTaskDraft`,
`taskDraftFromAitoTask`, `taskDraftToTaskCreate`.

`normaliseTaskDraft` matters most here. It is the localStorage boundary the new-project
drawer round-trips drafts through under a key that is not bumped when `TaskDraft` gains a
field, and it has already been bitten by exactly this class of change twice. Quantities
default through `num(...) ?? 1` (a quantity has no null state), discounts through
`num(...)` (null is meaningful).

### The service block (`frontend/src/components/aito/TaskStepFields.tsx`)

`renderPlainService` currently emits a bare cost input and a description. It becomes a
priced block:

```
┌─ Usinage ─────────────────────────────┐
│      Unit cost  [ 12 000        ]     │
│       Quantity  [ 3 ]                 │
│       Discount  [ 10% ▾ ]             │
│ ───────────────────────────────────── │
│                     32 400 XPF        │
│                     Line total        │
│                     10 800 per part   │
│                                       │
│ Usinage description                   │
│ [                                  ]  │
└───────────────────────────────────────┘
```

Three pieces are extracted so printing and the three plain services share them rather
than diverge:

- `QuantityInput` — the `max-w-20` numeric input, floor 1, currently inline in
  `ImpressionFields`.
- `DiscountSelect` — the `max-w-24` percent select (`—`, 5/10/15/20/25/30), currently
  inline in `TaskStepFields`.
- `ServicePriceFooter` — line total plus per-part rate.

The cost input takes the **unit** price and the draft stores unit × quantity. Editing the
quantity rescales the stored cost so the unit price holds — 500 apiece × 3 is 1500, not
500 spread ever thinner — which is the rule printing already follows at
`TaskStepFields.tsx:294`. The null-vs-0 rule stays owned by `CostInput`: clearing the
field emits `null` (service disabled), never `0`.

### Printing's unit-price readout

`discountedUnit` stops being gated on a discount existing. `ImpressionCostBand` states the
per-part rate always, matching the new blocks. The prop is renamed `unitRate` and its doc
updated — the old "undiscounted this would just echo the Cost input" reasoning no longer
holds now that three sibling blocks state it unconditionally.

### Read-only panel (`frontend/src/components/aito/TaskStepList.tsx`)

The `×N` meta line generalises to all four services, rendered under a step when its
quantity is 2 or more.

Printing keeps its existing always-on `×N`, including `×1`. That asymmetry is deliberate:
printing's meta line also carries material and colour, so `×1` there is one answer among
several, whereas a lone `×1` under a scan step would be noise. The existing suppression
rule for `0` is unchanged.

### Other frontend touch points

- `frontend/src/api/client.ts` — `AitoTask` and `AitoTaskCreate` gain the six fields.
- `frontend/src/components/aito/ImportQuoteDrawer.tsx` — maps the six from the import
  preview into the draft.
- `frontend/src/components/aito/services.ts` — `taskSteps` and `stagesWithWork` call
  `netCost`.
- i18n — one new key, `aito.serviceTotal` ("Line total"), translated in all 13 locales
  with real translations, not English placeholders (the i18n gate rejects those).
  `aito.printingTotal` retires into it. `aito.serviceUnitCost`, `aito.quantity`,
  `aito.discount` and `aito.perPart` already exist and are reused.

## Testing

Backend:

- Migration adds all six columns and is idempotent on a database that already has them.
- `net_cost` returns `None` for an absent service, the raw cost for one with no discount,
  and the discounted figure otherwise; `summarise` totals a project whose discount sits on
  a non-printing service.
- `rate_quantity` for each service, including the rounding case
  (`2401` over `2` → rate `1201`, total `2402`).
- `build_line_items` emits `quantity` and `discount` on a machining line.
- Round trip: export a task with quantity and discount on each of the four services,
  re-import the resulting line items, assert the task comes back unchanged.
- `_write_back_rounded_costs` adjusts every service's cost, not just impression.

Frontend:

- `netCost` mirror against the shared contract fixture.
- Editing quantity in a plain service block rescales the stored cost, keeping the unit
  price.
- Clearing the cost input disables the service (`null`, not `0`) even with a quantity set.
- Footer states line total and per-part rate; per-part reflects the discount.
- `normaliseTaskDraft` fills the six fields from a blob written before they existed.
- `×N` renders under a machining step at quantity 3 and not at quantity 1; printing still
  shows `×1`.
- Printing's band states the per-part rate with no discount set.

## Deliberate behaviour change

Scan, modélisation and usinage rates are now rounded to whole units on export, because
`rate_quantity` rounds and Books runs at `price_precision: 0`. Today those three pass
their raw cost through unrounded, so a scan quoted at 3500.5 is pushed as 3500.5 and Books
rounds it silently. After this change the app rounds it, and
`_write_back_rounded_costs` writes the achievable figure back onto the task — so the
project and the quote agree immediately instead of drifting until the poller pulls the
number back. This is the behaviour printing has always had.

## Known limits

- Books matches headers by name, so two same-titled tasks still render under one shared
  header. Unchanged by this work.
- A flat-amount discount typed directly in Books is still read as "no percent discount"
  and is overwritten on the next push, exactly as it is for printing today.
